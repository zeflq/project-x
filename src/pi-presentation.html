What even IS an agent?

❌ COMMON MYTH
"It just sends your prompt to ChatGPT and prints an answer."
→ One-shot. No memory.
→ Can't DO anything.
→ No loop. Just Q&A.
✅ WHAT pi ACTUALLY DOES
"It LOOPS until the job is done, using real tools at each step."
→ Reads your files
→ Runs bash commands
→ Edits code surgically
→ Checks results, repeats

● AGENTS.md + pi context always present, every call

Context Window — what's inside
● Compaction summary replaces old turns when full
● Recent turns from Session grows turn by turn
● Tool calls & results truncated to 50KB each
● Current user message your new input
Key insight: AGENTS.md never gets pushed out by compaction — it's in the system prompt. But it burns tokens on every call. The context window is what compaction manages — old turns get summarized so recent turns always fit.

The Agent Loop

packages/agent-core · the heart of pi
👤User Input
📤Result
AGENT
LOOP
🧠LLM
🔧Tool Call

1. User Input

You type a task. Natural language, no special syntax required.

2. LLM thinks

Model reads context + tool definitions, decides the next action.

3. Tool Call

Model emits a structured call: read / write / edit / bash.

4. Result back

Tool output is injected into conversation. Loop repeats until done.

4 Tools. That's it.

"By default, pi gives the model four tools: read, write, edit, and bash"
📖 read
Read any file or directory. The model's eyes on your codebase. Supports offset and limit for large files.
read("src/auth/login.ts")
✏️ write
Create new files from scratch. Used when generating boilerplate, new modules, or test files.
write("src/utils/token.ts", content)
🔧 edit
Surgical string replacement in existing files. Preserves context, produces minimal diffs.
edit(file, oldText, newText)
⚡ bash
Run any shell command. Tests, installs, git, linters — full shell access with timeout support.
bash("npm test -- auth")

@pi-coding-agent

The CLI you run. Orchestrates everything. Bundles core loop with coding-specific tools and TUI.

@pi-agent-core

The loop engine. Manages AgentState, turn lifecycle, tool execution (parallel & sequential), hooks.

@pi-ai

LLM abstraction layer. Handles streaming, thinking blocks, credential resolution. Provider-agnostic.

@pi-tui

Terminal rendering with differential updates. Multi-line editor, autocomplete, markdown, theming.

@pi-web-ui

Embed the agent in your own web application. ChatPanel and AgentInterface components.

Opinionated, but in a good way

No MCP
Build CLI tools with READMEs (Skills). Or add MCP via extension — your call. Keeps the core lean.
No sub-agents
Spawn pi via tmux. Or build your own multi-agent flow with extensions. No opinionated design forced on you.
No permission popups
Run in a container. Build your own confirmation flow with extensions inline with your security requirements.
No plan mode
Write plans to files. Real files. Version controlled. Or build your own with extensions.
No background bash
Use tmux. Full observability, direct interaction. Every command is visible and stoppable.
Extension system
Add tools, slash commands, lifecycle hooks via TypeScript. Loaded at runtime with jiti — no compilation.

Extend pi in TypeScript

Drop a .ts file in ~/.pi/agent/extensions/ — done.
my-extension.ts
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";
import { Type } from "typebox";

export default function (pi: ExtensionAPI) {

  // React to lifecycle events
  pi.on("session_start", async (_event, ctx) => {
    ctx.ui.notify("Extension loaded!", "info");
  });

  // Block dangerous bash commands
  pi.on("tool_call", async (event, ctx) => {
    if (event.toolName === "bash" &&
       event.input.command?.includes("rm -rf")) {
      const ok = await ctx.ui.confirm("Dangerous!", "Allow?");
      if (!ok) return { block: true, reason: "Blocked" };
    }
  });

  // Register a custom tool the LLM can call
  pi.registerTool({
    name: "deploy",
    description: "Deploy to staging",
    async execute() { return runDeploy(); },
  });

  // Register a /slash command
  pi.registerCommand("deploy", {
    description: "Deploy to staging",
    handler: async (args, ctx) => {
      ctx.ui.notify("Deploying…", "info");
    }
  });
}

pi.registerTool() · pi.registerCommand() · and more
pi.registerTool(def)
Add a tool the LLM can call. Supports promptSnippet, renderCall, renderResult.
pi.registerCommand(name, opts)
Add a /slash command. Tab-completable with getArgumentCompletions.
pi.registerShortcut(key, opts)
Bind keyboard shortcut e.g. ctrl+shift+p.
pi.registerFlag(name, opts)
Add a CLI flag. Read it with pi.getFlag().
pi.sendUserMessage(content)
Send as user. deliverAs: "steer" | "followUp".
pi.setActiveTools(names[])
Enable / disable tools at runtime.
pi.setModel(model)
Switch model. Returns false if no API key.
pi.appendEntry(type, data)
Persist state in session (not LLM context).
pi.setSessionName(name)
Label session in the /tree selector.
pi.exec(cmd, args, opts)
Shell helper — returns stdout / stderr / code.
